# P0–T1 implementation acceptance

Date: 2026-09-27. This is deterministic repository-level acceptance; it does
not claim measured improvement in agent task quality.

## Executed checks

The following command passed for generation, Harness review, discovery, drift,
and the CLI:

```text
go test ./internal/generation/... ./internal/harness/... ./internal/discovery/... ./internal/drift/... ./cmd/harnessforge
```

The tests cover structured skills and workspace gates, generated-file ownership
and preservation of human edits, evidence and content changes after review,
idempotent discovery plus same-ID conflicts, and the distinction between
evidence presence, coverage, and rule conformance. `git diff --check` also
passed.

## Static clone fixture

`testdata/clones/without-forge/` contains separate Codex and Claude Code clones.
Each has its native instruction file and a small Go project; neither includes a
`.harness/`, `.forge/`, generation manifest, or HarnessForge binary. The focused
`TestWithoutForgeClonesPreserveExportedContract` test checks those absences,
required approved rule text, skill references and contents, the test gate, and
the independent Go module manifest for both clones.

No external agent was run against the fixture. The fixture proves that native
instructions are available in a clone without Forge; it does not establish that
a particular agent version discovers or follows every instruction. That requires
the versioned adapter acceptance and pilot described later in the plan.

## Limits

`sync`, generated-manifest reconciliation, automated clone execution, and the
full cross-platform suite are not part of this acceptance run. They remain in
T2–T5. This acceptance is not evidence that HarnessForge improves correctness,
time, or token use.
